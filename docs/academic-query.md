# 成绩与课表共用扫码登录

用户要求将“学业成绩”和“学分绩点”合并，并允许登录态保留一天。2026-09-24 授权发布：先更新现有 `schedule.wiki.jianges.com` 后端至 `20260924-1`，再通过 GitHub main 发布 Wiki；无需另建服务器、域名或前端网站。

## 页面与数据

- `/study/grades`：`content/2.study/3.grades.md` 装配 `GradeQuery.vue`，查询、学期筛选、课程搜索、成绩表及原有学分绩点说明。
- `/study/gpa`：`app/pages/study/gpa.vue` 跳转到合并页；静态生成输出 meta refresh。原学分绩点卡改指向成绩与绩点，侧栏只保留一个条目。
- `/study/curriculum`：`AcademicSchedule.vue` 复用原 `ScheduleBoard.vue` 和七天课程缓存。先加载缓存再装配扫码组件，避免已有课表时抢先生成二维码。
- `SchoolAcademicQuery.vue` 共用登录、串行轮询、退出、恢复和错误处理。首次立即轮询，后续约 3.1 秒起始间隔；有效课表缓存打开时不查询后端，点击刷新才使用会话。
- 查询输入框和课表下拉框参照顶部搜索框，统一 34px 高、14px 字号、6px 圆角。

“学分与绩点”栏目由第二个 `GradeQuery`（`calculator-only`）装配 `GradeGpaCalculator.vue`，与上方查询共享当前页面内存结果；退出登录或离开查询页时清除。点击计算按教务返回的课程绩点进行学分加权，不将分数自行换算成绩点。`app/utils/gpa.ts` 按课程编号合并重复记录，优先按补重学期、其次按开课学期选择最新；同学期标为补考/重修的记录优先于正常考试。先后不明确时要求手动选择，不按最高分或接口顺序猜测。无编号的课程独立保留，缺少有效学分/绩点的课程不计入，0 绩点正常计入。支持取消勾选课程；修改选择后需重新计算。界面注明“绩点计算仅供参考，请以学校通知为准”。

课程选择按当前采用记录的补重学期（无则开课学期）分组，各学期可批量全选/取消，支持部分选中的中间态；同课程仍只计入一条记录。加权公式使用项目已有的 remark-math/KaTeX 渲染 LaTeX 分式，不新增公式库。

教务官网的实际成绩页面为 `https://bkjx.wust.edu.cn/jsxsd/kscj/cjcx_frm`，嵌套 `cjcx_query` 和 `cjcx_list`，这些地址没有 `.do` 后缀。2026-09-24 已从用户打开的实际官网页面核对，再通过扫码建立的服务端会话 GET `cjcx_list`。使用 `parse5` 按表头映射课程、学期、编号、成绩、学分、绩点、课程性质、考核方式、考试性质、成绩标识、分组和补重学期；保留非数字成绩和重复考试记录，不自行转分、不去重、不计算学校总 GPA。未知表格与登录页面不能当作空成绩。

## 会话边界

`server/utils/academic-store.mjs` 复用学校扫码适配器、受限来源 HTTP 客户端和独立 Cookie jar。

- 二维码仍最多 3 分钟；认证成功时切换为固定 `24 × 60 × 60 秒`，浏览或查询不续期。
- 后端内存保存学校 Cookie；不写磁盘、不返回给 Wiki，也不保存密码。官方扫码产生的临时票据交换后丢弃。
- 浏览器 localStorage 只保存本服务随机 256 位 bearer 令牌及固定到期时间，键按 API base 隔离。令牌可访问该用户的教务结果，属于登录凭据，不放 URL 或日志。请求必须匹配创建会话时的 Origin。
- 学校提前失效返回 401 并删除会话；退出立即销毁后端 Cookie 和令牌。重启后需重新扫码，24 小时是最长保留时间，不保证学校会话持续一天。
- 成绩只在当前页面内存显示，离页即释放；后端每种查询结果短暂复用 60 秒，减轻学校负担。课表的七天缓存独立于登录态，退出不会删除已保存课表，“清除本机课表”独立操作。
- 多标签页同步退出/切换登录，取消和退出后的迟到响应不能恢复成绩。页面关闭不销毁已认证会话，仅销毁尚未完成的二维码会话。
- 正式 HTTP 服务沿用原 HTTPS/CORS/Host/限流检查，最多 20 个待扫码、200 个总会话；这些是保护配置，不是压测结果。

## 接口

POST `/api/academic`，JSON，后续带 `Authorization: Bearer <sessionToken>`，浏览器 `credentials: omit`。返回 `Cache-Control: private, no-store`。

| action | 附加参数 | 结果 |
| --- | --- | --- |
| start | 无；不带旧令牌 | 二维码、三分钟到期时间及 sessionToken |
| poll | 无 | waiting/scanned 或 authenticated 与固定24小时到期时间 |
| inspect | 无 | 现有会话状态，不延长有效期 |
| query | resource: grades 或 schedule | complete + result + fetchedAt；上游格式变化返回 needs_adapter |
| logout | 无 | 销毁会话 |

保留旧 `/api/login-template` 及三种实验模板的行为，供兼容与回归。原 `ScheduleQuery.vue` 和相应旧调度测试属于旧短期会话入口，新正式装配使用上述共享组件。

## 本地运行与验证

`pnpm dev:login:lan` 继续使用 3017，另启动仅监听 `127.0.0.1:3019` 的开发会话进程。Nuxt `/api/academic` 在开发且明确启用时转发到它。该进程不会因 Nuxt 热更新而丢失登录；只对成绩解析模块按文件版本加载，方便核对学校结构。这个开发入口不打包到正式后端。退出开发命令会停止两个子进程。

- `pnpm check:academic`：24小时固定边界、来源隔离、退出撤销、迟到结果、缓存、非数字成绩、字段顺序、共享组件恢复与轮询节奏。

- `pnpm check:content`、`pnpm typecheck`、`pnpm generate`：内容、类型和静态构建。
- 真实扫码：本地获取23条成绩，课程名、成绩、学分、绩点逐行与官网对比一致；学期筛选10条、课程搜索2条验证；成绩→课表刷新→成绩均不需要再次扫码。测试未将个人成绩或认证材料写入仓库。
