## 发布与验证

执行 `pnpm check:content`、`pnpm check:xupt`、`pnpm typecheck`、`pnpm generate`；静态产物在 `.output/public/`，必须包含模型和海报。用 `pnpm preview:static` 检查 `/campus/map`，确认模型、旋转缩放、重置、全屏、深浅色及 390px 手机布局正常。切换全屏应保留当前视角。

实际托管应返回 GLB 文件，避免把模型路径重写成 HTML。固定文件名更新时需要刷新站点缓存；需要长期缓存时改用带版本或内容哈希的文件名并同步加载地址。

桌面浏览器与手机尺寸预览不能代替手机真机性能验收。继续导入其他建筑时分别发布单栋模型，只加载当前需要的楼栋；完整校园加载策略应根据实际传输、内存和帧耗时另行验证。

## R2 整校接入（2026-11-16）

本地教一入口继续可用。设置构建环境变量 `NUXT_PUBLIC_CAMPUS_MANIFEST_URL` 后，页面从该 URL 读取版本清单，点击“加载全校园”后加载其中的分块。清单必须含非空字符串 `version`，以及包含 `path`、正整数 `bytes` 的 `parts` 数组。相对资源路径基于清单 URL 解析。压缩传输由浏览器自动解压，`bytes` 为解压后的 GLB 字节数。

接入点为 `app/utils/campus-model.ts`、`CampusScene.client.vue` 和 `nuxt.config.ts`。请求支持失败重试入口和离页取消，模型按原比例显示，采用设备像素比及抗锯齿。默认本地模型路径保持 `/models/campus/teach1.glb`。

模型资源位于 R2 的 `wust-models` 桶。给桶绑定实际资源域名，配置允许 Wiki 来源的 GET、HEAD 跨域请求，并为版本模型设置缓存规则。构建变量应填写资源域名下 `/campus/latest.json` 的完整 HTTPS URL。设置后重新运行 `pnpm generate`，静态产物会写入该配置。

本次 r091 导出包与上传器位于建模项目 `deliverables/wiki-campus-r091-20261116/`，详细步骤见其 README。上传器验证全部分块后最后更新 `latest.json`，后续模型更新可复用同一公开清单地址。上传凭据保存在上传端的本机配置中。

接入代码已通过内容、组件来源、类型及静态生成检查。修复包通过 HTTP 全量下载、gzip 解码、SHA-256、清单校验和取消处理检查。R2 上传和自定义资源域名已完成，详见文末发布记录。此处为首次接入检查记录。

## 逐块显示与深度缓冲修复（2026-11-16）

`CampusScene.client.vue` 在下载 GLB 前创建画布，每完成一个分块的下载与解析就加入场景并请求一帧绘制。首块出现后可以操作视角，底部显示已完成分块数；用户开始操作后不再因新增分块自动重置视角。后续请求失败时保留已经显示的部分，重试会重新开始该次加载。离页或重试会取消原请求并释放对应资源。整校仍会下载全部分块，首屏改善不表示总流量或最终显存下降。

湖面抖动检查使用导出包 part-066 的实际湖面与校园底层地面。湖面高度约 0.05，地面高度为 0，80 个湖面顶面采样点均存在底层地面。抽查的湖面顶面没有完全重复三角形。逐块加载版本的相机近裁剪面为场景半径除以 10000、远裁剪面为半径乘以 40；普通透视深度会使部分远景表面的深度相同。

网页渲染器启用 `logarithmicDepthBuffer: true`，保留现有近距离查看能力。模型坐标、湖面高度、材质和 GLB 文件未因本次深度修复而修改。没有对所有材质施加任意偏移。真正完全共面的不同面片仍需单独检查。

数值回归脚本在建模项目 `deliverables/wiki-campus-depth-fix-20261116/audit-depth.py`。使用同一条屏幕射线与实际湖面、地面相交，对 80 个位置各做 257 次相机位置采样。20560 对交点中，普通 24 位深度产生 20221 对相同值，对数深度为 0 对相同值。该结果为数学投影检查，不能代替 GPU 画面复核。浏览器实际验收状态以同目录 `结论.md` 为准。
