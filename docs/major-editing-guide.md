# 本科专业列表填写指南

面向后续 agent。2026-09-13 根据用户要求及当前源码整理，开始工作时仍须核对实际文件。用户后续指令优先。

## 目标与当前范围

沿用用户提供的学院分类，把本科专业逐步装配成 Coder 原版翻面卡片。卡片覆盖当前维护范围内的学院与专业，但不要把页面内容当作招生填报或全校事实的唯一依据。

2026-09-13 已依据 2026 年本科招生计划补全为 22 个学院（部）、76 个独立本科专业卡片；招生大类、拔尖创新人才试验班、双学士学位项目和辅修方向仍保留在备注表中，不代表它们都是额外基础专业。

用户已明确的外观：不显示图标、紧凑卡片、桌面一行5个；背面学院名称上方显示灰色小字“所属学院”，地点信息只显示“教学楼”。当前响应式规则为1200px起5列、600–1199px为3列、599px及以下2列。保留原版翻面动画、键盘访问和减少动态效果适配。

## 新增一个学院的步骤

1. 先读取原 Markdown 对应学院及所有专业，不覆盖用户已有简称、备注或分类。以学院分组，不擅自换成学科门类；招生大类与具体专业是不同概念。
2. 核对当年招生网、本科生院及学院官网。记录专业归属、名称、网页链接、学院地点的来源和年份；发现与原文冲突时明确记录冲突，不能静默猜选。
3. 在 `majorColleges` 中添加稳定的英文键，参照现有字段填写：

| 字段 | 填写规则 |
| --- | --- |
| `name` | 学院正式名称，与正文标题对应 |
| `address` | 官网邮寄/联系地址，当前不在卡片展示；不要冒充校内楼宇 |
| `location` | 如“黄家湖校区 · 教三楼”；必须写校区，避免同名教学楼混淆 |
| `locationSource` | 能支持楼宇信息的具体官方文章URL，当前仅记录、不自动展示 |
| `teachingBuilding` | 黄家湖校区的上课/自习教学楼；来源为用户提供的《WUST2024级新生宝典》，不替代学院 `location` |
| `website` | 经确认的学院官网 |
| `majors[].name` | 完整专业名，保留中外合作等区别 |
| `majors[].tags` | 简称及必要短标签，用逗号分隔；不要堆长篇招生说明 |
| `majors[].url` | 实际官方目标地址，不使用推测域名或搜索结果页 |
| `majors[].label` | 与链接内容一致，如“学院官网”“官网专业介绍”“官网专业总览” |

4. 在该学院标题及简称之后插入 MDC 调用，`college` 必须与数据键一致：

```md
::major-cards{college="materials"}
::
```

5. 原表格保留在以下结构中，不丢弃招生方向、年份、简称辨析等备注。标签与表格之间保留空行，验证 Markdown 表格仍正常渲染：

```md
<details>
<summary>专业备注</summary>

原表格放在这里

</details>
```

6. 同步专业数据与原表格的名称、简称，避免两份信息分歧。追加来源记录，并验证实际页面。未完成全页核对前不要因增加卡片就把 `status: draft` 改为 published，也不要随意重写更新时间。

## 查证地点与官网

- 优先查学院“联系我们/组织机构”、办事指南，再用近期官方通知交叉核对。搜索词可用 `site:学院域名 办公室 教三楼`、`site:学院域名 学院 地址`。核对正文日期，搜索引擎抓取时间不等于发布年份。
- 学院地点、院系办公室、团委办公室、临时活动地点、专业上课楼、宿舍与报到点不可互相替代。一次会议只能证明该次活动在该楼，需结合其他办公信息再判断学院地点。
- 《WUST2024级新生宝典》中的“学校教学楼”属于黄家湖校区教学/自习楼速查，不作为学院 `location` 的单独证据；使用时应与学院官网办公地点、校区搬迁信息分开记录。
- 目前有足够依据的地点记录包括计算机“黄家湖校区 · 教三楼”、材料“青山校区 · 教六楼”、化学与化工“青山校区 · 教二楼”、艺术与设计“黄家湖校区 · 逸夫楼”、马德里康普顿斯“黄家湖校区 · 教十一楼 C 区”；依据见来源文档。这些记录不代表所有专业、所有年级都在该楼上课。
- 校团委目录可作其他学院的检索线索，但团委办公室不直接等于学院全部办公地点；学院调整后还需检查旧名称、旧地点是否适用。
- 社区可补充日常简称、校内叫法等线索，应注明来源和年份；不得以聚合页、孤立帖子证明正式专业设置或当前楼宇。没有可靠结果就保留待核实，不猜测具体楼号、房间号。
- 未确认地点时使用“待核实”，`locationSource` 留空，并在来源记录中说明；不能填一个无法支持结论的链接充数。
- **材料学院卡片链接由用户指定统一为 `https://cl.wust.edu.cn/`，显示“学院官网”**，不要又改回招生资料。其他学院沿用已核对的官网/专业介绍链接，不把材料学院域名批量复制到所有学院。
- 不添加无意义介绍、就业宣传或未获核实的个人联系人资料。

## 验证与交接

修改数据、Markdown或组件后，执行相关检查：

```powershell
pnpm check:content
pnpm check:xupt
pnpm typecheck
pnpm generate
```

浏览器预览 `/campus/major`，检查5列布局、悬停翻面、键盘访问、手机布局、背面文字不裁切、官网链接准确、原表格可展开。核实无运行时及组件解析错误。静态预览不会自动更新源码，需重新生成；使用终端确认的服务地址，不假定4178永远可用。

已有浏览器脚本需本机可解析 Playwright 并安装 Edge：

```powershell
$env:WIKI_QA_URL = 'http://127.0.0.1:4178'
node scripts/qa-major.cjs
```

脚本当前断言76张卡片、22个学院、22份备注表；专业数量变化后按实际数量更新这些断言，并保留布局、链接和交互检查。不要因数量变化删掉检查，也不要仅凭构建成功认定翻面正常。仅修改本指南无需重新构建应用。
