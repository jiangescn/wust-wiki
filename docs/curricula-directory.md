# 培养方案页面

入口仍为 `/study/status`；正文 `content/2.study/5.status.md`，组件 `app/components/content/CurriculumDirectory.vue`。用户已选择平铺布局作为正式实现：默认本科，按学院分组平铺专业卡片，支持研究生切换、搜索、仅有资料和学院快速定位。每个专业先列两份文件，其余版本可展开；未取得完整方案的专业保留缺失状态。PDF 同时提供在线查看与直接下载，DOC 提供下载。

已移除两版切换器与原型组件命名；旧的 `?variant=flat`、`?variant=select` 链接均显示同一个平铺页面，不再选择布局。目录和附件继续直接使用现有 `app/data/curricula.json` 与公开文件，没有新增数据采集或后端。

## 交互与样式

- 侧栏“补充培养方案”链接到项目 GitHub Issues；直接复用原博客示例的 `meta-aside-*` 插槽与 `BlogLinkCard`，通过 `DocsArticleAside.vue` 适配普通文档，手机上显示在正文前。
- 卡片圆角为 12px，控件圆角为 6px；学院之间保留独立水平分隔线。
- 学院名使用 `h2` 二级标题，桌面 24px、手机 20px，加大标题下方间距；专业名保持三级标题，避免层级混淆。
- 筛选复用 `WikiMotion` 的 160ms 轻淡入（透明度从 0.85 到 1），不对整个长目录插值高度。
- 其他版本使用原生 `details`，复用全局 220ms 展开动画及 16px 旋转箭头。系统开启“减少动态效果”时关闭这些动效。

## 更新

原始采集归档 `docs/curricula/` 保留在维护者本地，不随公共仓库发布。公开仓库保存生成目录、来源清单和白名单附件，直接运行 `pnpm generate` 即可构建网站；下列重新生成与归档比对命令需要本地原始归档。普通贡献者可通过 Issue 提交文件和来源。

1. 更新对应归档索引与来源说明，核对专业、版本和项目边界。
2. 运行 `pnpm build:curricula`，生成 `app/data/curricula.json`、`docs/curricula-public-manifest.json` 和 `public/files/curricula/` 白名单附件。补充文件映射在 `scripts/build-curricula-catalog.mjs` 中明确列出，不递归公开整个归档。
3. 运行 `pnpm check:curricula` 检查索引一致性、PDF/DOC 签名、公开副本 SHA-256 和本科基线数量；再执行类型与内容检查、静态生成，验证层次切换、搜索、仅有资料、学院定位、版本展开、文件打开、减少动态效果、深浅色及手机布局。

本次目录包含 236 个本科/研究生专业与项目条目（含缺失条目、历史专业及学位类别），193 份去重后的公开附件，共约 374 MiB。这些数量不代表 236 份已核实的当前培养方案。页面首次只加载目录，附件点击后加载；没有新后端或登录要求。后续发布需要包含生成目录及公开附件，开发归档本身不是运行时依赖。

外部学校网页沿用归档中的已知来源，本次未逐一重新验证外网可用性。实际执行版本以学校和学院通知为准。
